# Password-Analyser

A Python-based tool designed to automate the analysis phase of Active Directory password audits.

Developed as a Proof of Concept to accompany [Password Audits Part 4: Analysing Results](https://mollysec.com/posts/password-audits-part-4/).

It consumes recovered password datasets and supporting artefacts generated by [`ntds-organiser`](https://github.com/CSpanias/ntds-organiser) and produces statistics, evidence tables, executive summaries, technical commentary, and remediation guidance in Markdown format.

## Installation

### UV (Recommended):

```bash
# Install UV
curl -LsSf https://astral.sh/uv/install.sh | sh

# Install password-analyser via UV
uv tool install git+https://github.com/CSpanias/password-analyser

# Verify installation
password-analyser -h

# Update
uv tool upgrade password-analyser
```

### Clone Locally

> Note: Python 3 must be installed and available in your `PATH`.

```bash
# Clone the repository
git clone https://github.com/CSpanias/password-analyser /opt/password-analyser

# Make the script executable
chmod +x /opt/password-analyser/password_analyser.py

# Create a symbolic link
sudo ln -s /opt/password-analyser/password_analyser.py /usr/local/bin/password-analyser

# Verify installation
password-analyser -h
```

## Features

* Overall password recovery and crack-rate statistics
* Recovered privileged accounts
* Domain password policy violations
* Password reuse across accounts and/or between similarly-named accounts
* Username-derived passwords
* Organisation-related passwords
* Common dictionary password terms, date-related passwords, and keyboard walks
* Password frequency trends
* Character class adoption
* Password length distribution
* Automatic report generation (executive summary, commentary, and remediation guidance)

## Usage

**Run `password-analyser` from the directory containing [`ntds-organiser`](https://github.com/CSpanias/ntds-organiser)**. The files `domain-admins.txt`, `domain-policy.txt`, `company-words.txt`, and `enabled-users.txt` are loaded automatically from the ntds-organiser output directory, leaving only the mapped passwords file to be specified manually.

```bash
# Help menu
$ password-analyser -h
usage: password-analyser [-h] -M MAPPED_PASSWORDS [-A DOMAIN_ADMINS] [-P PASS_POLICY] [-C COMPANY_WORDS] [-E ENABLED_USERS]

[*] Password Analyser v1.0

options:
  -h, --help            show this help message and exit
  -M, --mapped-passwords MAPPED_PASSWORDS
                        Recovered NTLM passwords file
  -A, --domain-admins DOMAIN_ADMINS
                        Domain Admin account list (default: ./ntds-organiser/domain-admins.txt)
  -P, --pass-policy PASS_POLICY
                        Domain password policy (default: ./ntds-organiser/domain-policy.txt)
  -C, --company-words COMPANY_WORDS
                        Organisation-specific password analysis terms (default: ./ntds-organiser/company-words.txt)
  -E, --enabled-users ENABLED_USERS
                        Enabled user accounts list (default: ./ntds-organiser/enabled-users.txt)

# Basic Analysis
password-analyser -M mapped-passwords.txt

# Full Workflow
password-analyser -M mapped-passwords.txt -A domain-admins.txt -P domain-policy.txt -E enabled-users.txt -C company-words.txt
```

## Example Output

```bash
password-analyser -M mapped-passwords.txt -A domain-admins.txt -P domain-policy.txt -E enabled-users.txt -C company-words.txt

[+] Markdown report written to: report.md
```
